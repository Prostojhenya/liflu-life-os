# Настройка Push-уведомлений для заблокированного экрана

## Проблема
Уведомления приходили только когда экран разблокирован.

## Решение
Реализована полная поддержка Firebase Cloud Messaging (FCM) с серверными push-уведомлениями.

## Что было сделано

### 1. Обновлен Service Worker (`public/firebase-messaging-sw.js`)
- Добавлены параметры для показа уведомлений на заблокированном экране
- Добавлена вибрация и звук
- Настроен параметр `renotify: true` для повторных уведомлений

### 2. Серверные функции (`functions/src/index.ts`)

#### `sendPushNotification`
Автоматически отправляет push-уведомление при создании записи в коллекции `notifications`:
- Поддержка Android с приоритетом `high` и видимостью `public`
- Поддержка iOS с `contentAvailable` и звуком
- Автоматическая очистка недействительных FCM токенов

#### `checkScheduledNotifications` (новая функция)
Проверяет запланированные уведомления каждые 5 минут:
- Сканирует всех пользователей с активными уведомлениями
- Отправляет уведомления, время которых наступило
- Добавляет уведомления в историю
- Удаляет отправленные запланированные уведомления

### 3. Клиентская часть

#### `NotificationCenter.tsx`
- Автоматическое сохранение FCM токена в профиль пользователя
- Обработка входящих FCM сообщений
- Показ локальных уведомлений для активного приложения

#### `notifications.ts`
- Функции для планирования уведомлений о задачах и привычках
- Сохранение в Firestore для серверной обработки

### 4. PWA Манифест (`public/manifest.webmanifest`)
- Настроен для корректной работы как PWA
- Добавлены ярлыки для быстрого доступа
- Настроена ориентация и цвета

## Как это работает

### Для мгновенных уведомлений:
1. Приложение создает запись в `users/{userId}/notifications`
2. Cloud Function `sendPushNotification` автоматически срабатывает
3. FCM отправляет push-уведомление на устройство
4. Service Worker показывает уведомление (даже на заблокированном экране)

### Для запланированных уведомлений:
1. Приложение создает запись в `users/{userId}/scheduledNotifications`
2. Cloud Function `checkScheduledNotifications` проверяет каждые 5 минут
3. Когда время наступает, отправляется FCM уведомление
4. Запись перемещается в историю уведомлений

## Настройки для разных платформ

### Android
- `priority: 'high'` - высокий приоритет доставки
- `visibility: 'public'` - показывать на заблокированном экране
- `defaultSound: true` - звук по умолчанию
- `defaultVibrateTimings: true` - вибрация по умолчанию

### iOS (Safari/PWA)
- `contentAvailable: true` - доставка в фоне
- `sound: 'default'` - звук по умолчанию
- Требуется добавление сайта на домашний экран

### Desktop (Chrome/Edge/Firefox)
- Работает через Service Worker
- Показывает нативные уведомления ОС

- Откройте приложение

### 2. Проверить FCM токен

1. Создайте тестовое уведомление
2. Заблокируйте экран устройства
3. Уведомление должно появиться на экране блокировки

## Требования

### Для работы на мобильных устройствах:
1. **Android**: Chrome 42+, установка PWA не обязательна
2. **iOS**: Safari 16.4+, **требуется** добавление на домашний экран
3. **HTTPS**: обязательно (или localhost для разработки)

### Для iOS:
- Пользователь должен добавить сайт на домашний экран
- Открыть приложение хотя бы один раз
- Разрешить уведомления

## Частые проблемы

### Уведомления не приходят на iOS
- Убедитесь, что сайт добавлен на домашний экран
- Проверьте, что приложение открывалось хотя бы раз
- Проверьте настройки Safari: Settings > Safari > Advanced > Experimental Features > Notifications

### Уведомления не приходят на Android
- Проверьте разрешения в настройках браузера
- Убедитесь, что не включен режим энергосбережения
- Проверьте, что уведомления не заблокированы для сайта

### FCM токен не сохраняется
- Проверьте VAPID ключ в `.env`
- Убедитесь, что Service Worker зарегистрирован
- Проверьте консоль на ошибки

## Оптимизация

### Частота проверки
Текущая настройка: каждые 5 минут. Можно изменить в `functions/src/index.ts`:
```typescript
schedule: 'every 5 minutes' // или 'every 1 minutes', 'every 10 minutes'
```

### Батарея
- Уведомления отправляются через FCM (энергоэффективно)
- Проверка на сервере (не расходует батарею клиента)
- Service Worker работает только при получении уведомления

## Безопасность

- FCM токены хранятся в Firestore с правилами безопасности
- Только владелец может читать свои уведомления
- Токены автоматически удаляются при выходе
- Недействительные токены очищаются автоматически
